# PYNQ Overlays

## Introduction

Parallel overlay designs are hosted under each board, leveraging a shared set of vivado tcl scripts located at `scripts`,
where a version of vivado 2022.1 is expected, to automate the building process, following the AMD PYNQ workflow.

Developers are encouraged to plugin IP cores, and in particular, RTL designs which can be integrated in the block diagram
through the building process. An example can be found in the `ZCU208/mts_8ch` overlay.

## Overlay source file structure

For an overlay named `<design>`, the following 3 files are expected under `<BOARD>/<design>`:

* `Makefile`

    | Variable |                                      Description                                     |
    |:--------:|:------------------------------------------------------------------------------------:|
    |   BOARD  | Board name, currently `zcu208`, `zcu216` and `lbl208` are supported.                 |
    |   JOBS   | Number of parrallel jobs, increase building speed at a cost of computer memory;      |
    | OVERLAY  | Design name string, also used as the vivado project name.                            |
    |  RTL_SRC | A list of RTL source files, imports into vivado project by  `import_files` command;  |
    |  TCL_SRC | A list of tcl files, for additional IP creation;                                     |
    |    XDC   | A single vivado xdc constraint file.                                                 |

* `<design>.tcl`:
    A product exported by vivado block diagram by `File->Export->Block Design`, or the `write_bd_tcl` command.
    It is preferred to validate the block diagram before exportation.
* `<design>.xdc`:
    vivado xdc constraint file, on top of known board constraints defined by `board_part` property, which is `xilinx.com:zcu208:part0:2.0` for ZCU208 board.

Additional source files:

* `ddr4.dts`:
    Linux device tree source file, in corresponding to the overlay's 8GB DDR4 memory instantiation.
    The compiled `ddr4.dtbo` file is a plugin segment of the device tree, and can be inserted by the overlay driver at runtime.

* `CLK104/*.tcs`:
    TICS files for programming LMK04828 and LMX2594 chips on the CLK104 board, defining the clocking configuration to the RFSoC.
    These files are generated by vendor tools like TI TICS pro software.
    These files are loaded by overlay drivers at runtime, see `mimo_mts/utils/config_clk104.py`.

## Building process and products

The final products of an overlay are 2 files: bitstream `<design>.bit` and hardware handoff file `<design>.hwh`.
They will be available under `overlays/<design>` once building is complete, under the `<design>/_xilinx/` directory.

A series of steps are executed, as listed by commands available by `make help`.
For example, the block diagram itself can be generated by `make block_diagram` without synthesizing and implementation,
allowing quick design iterations.

A Continuous Integration (CI) building process is enabled by `.gitlab-ci.yml`, which can be used as a reference. CI builds 3 overlays at every git commit.
